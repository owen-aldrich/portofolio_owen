# Design Document — Owen Aldrich Portfolio

## Overview

The portfolio is a React 18 + Vite 5 single-page application (with one secondary route) deployed as a fully static build on Vercel. It presents Owen Aldrich Setiawan's professional identity, projects, certificates, technical stack, and capabilities through a pixel-accurate implementation of a Figma design. All dynamic content is sourced from a single data file (`src/data/content.js`) so that adding or updating content never requires changes to component code.

The implementation is intentionally minimal: plain JSX, Tailwind CSS utility classes only, react-router-dom v6 for routing, and Web3Forms for contact form submission. No UI component kits, animation libraries, or server-side runtime are introduced.

### Key Design Goals

- **Figma fidelity**: Every spacing value, color, radius, shadow, font size, and font weight is taken directly from the Figma design file. No values are invented or approximated.
- **Data-driven rendering**: All repeating content (project cards, certificate cards, stack icons, capability cards) is generated by mapping over Content_Store arrays — no hardcoding in component JSX.
- **Static deployability**: Zero server-side runtime. The build output is a flat directory of HTML, JS, and CSS assets.
- **Graceful image degradation**: All image slots show a styled `PlaceholderImage` block when the referenced file is absent — no broken image icons, no layout shifts.
- **Mobile-first responsive layout**: Base styles target 390px; `md:` breakpoint (768px+) activates desktop layouts.

## Architecture

### Application Shell

```
BrowserRouter (main.jsx)
  └── App.jsx  (route definitions)
        ├── /                   → HomePage
        ├── /projects/:slug     → ProjectDetailPage
        └── *                   → redirect to /
```

`main.jsx` mounts `<BrowserRouter>` around `<App>`. `App.jsx` defines the two routes plus a catch-all redirect using react-router-dom v6 `<Routes>` / `<Route>` / `<Navigate>`.

### Page Composition

**HomePage** assembles sections in document order:
```
Navbar
main
  HeroSection
  AboutSection
  WorkSection
    TabSwitcher (local state: activeTab)
    ProjectsPanel  (when activeTab === 'projects')
    CertificatesPanel (when activeTab === 'certificates')
  CoreStackSection
  CapabilitiesSection
  ContactSection
Footer
```

**ProjectDetailPage** fetches the matching project object from Content_Store by slug, then renders:
```
Navbar
main (pt-[120px])
  BackLink
  ProjectTitleBlock
  ProjectImage
  ProjectInfoCard
    (Description + TechStack) / (Features + Outcomes)
    CTAButtons (GitHub, Live Demo — conditional)
Footer
```

If no project matches the slug, the page renders `<Navigate to="/" replace />` immediately.

### Data Flow

All content flows in one direction: `content.js` → page/section component → card/display components. No global state manager (Redux, Zustand, Context) is needed. The only runtime state is:

| Component | State | Type |
|---|---|---|
| `WorkSection` | `activeTab` | `'projects' \| 'certificates'` |
| `ContactSection` | `formState` | `{ name, email, message }` |
| `ContactSection` | `submitStatus` | `'idle' \| 'submitting' \| 'success' \| 'error'` |
| `Navbar` | `menuOpen` | `boolean` (mobile hamburger) |
| `CertificatesPanel` | `activeCertificate` | `object \| null` |

### Icon Loading Strategy

Tech icons are SVG files stored in `src/assets/icons/`. They are resolved at build time using Vite's `import.meta.glob`:

```js
// Inside IconBox.jsx (or inlined in CoreStackSection)
const icons = import.meta.glob('../../assets/icons/*.svg', { eager: true, import: 'default' });
// icons['../../assets/icons/react.svg'] === '/assets/icons/react-abc123.svg' (resolved URL)
```

The `IconBox` component receives `{ icon, name }` — if `icons[key]` resolves, it renders an `<img>`; otherwise it falls back to a text badge. This means adding a new icon requires only: (1) dropping an SVG into `src/assets/icons/` and (2) adding one entry to `content.js`.

## Components and Interfaces

### Component Prop Contracts

#### `PlaceholderImage`
```jsx
<PlaceholderImage className="..." style={{ width, height }} />
```
Renders a `<div>` with `bg-[#eeeeed]` and the passed `className`/`style`. No `<img>` tag — no broken-image icon possible.

#### `Navbar`
No props. Reads `navLinks` from `content.js`. Internal state: `menuOpen` (boolean).
- Desktop: renders logo, pill-nav with active/inactive link styles, CTA button.
- Mobile (`< md`): renders logo + hamburger button; toggles a dropdown menu of nav links.
- Scroll behavior: links call `document.getElementById(id).scrollIntoView({ behavior: 'smooth' })` for same-page anchors; the "Get in Touch" CTA does the same for the contact section.

#### `HeroSection`
No props. Reads `personal` from `content.js`.
- Desktop: 12-column grid, left cols text content, right col portrait card.
- Portrait image: `<img src="/images/profile/hero.jpg" />` wrapped in a card; `onError` swaps to `<PlaceholderImage>`.

#### `AboutSection`
No props. Reads `personal` from `content.js`.
- Focus chips rendered from `personal.focusChips` array.
- About photo: same `onError` → `PlaceholderImage` pattern.
- Info bar: three labeled values (location, status, focus) from `personal`.

#### `WorkSection`
No props. Reads `projects` and `certificates` from `content.js`.
- Owns `activeTab` state, passes nothing down — `ProjectsPanel` and `CertificatesPanel` read directly from content.js or receive data as props.
- Tab switcher renders two buttons; active tab gets white bg + border-primary style.

#### `ProjectsPanel`
```jsx
<ProjectsPanel projects={projects} />
```
Maps `projects` → `<ProjectCard>` inside the outer white panel card.

#### `ProjectCard`
```jsx
<ProjectCard project={project} />
```
`project` shape: `{ slug, title, description, year, category, coverImage }`. Navigates to `/projects/${slug}` on "View details" click.

#### `CertificatesPanel`
```jsx
<CertificatesPanel certificates={certificates} />
```
Owns `activeCertificate` state. Maps `certificates` → `<CertificateCard>`. Renders `<CertificateModal>` as a portal when `activeCertificate !== null`.

#### `CertificateCard`
```jsx
<CertificateCard certificate={certificate} onOpen={fn} />
```
`certificate` shape: `{ title, issuer, platform, date, image, grade, pdfUrl, description }`. Calls `onOpen(certificate)` on click.

#### `CertificateModal`
```jsx
<CertificateModal certificate={certificate} onClose={fn} />
```
Rendered via `ReactDOM.createPortal` into `document.body`. Closes on backdrop click or close button click. Blocks body scroll while open (`overflow-hidden` on `document.body`).

#### `CoreStackSection`
No props. Reads `coreStack` from `content.js`.
- `coreStack` array shape: `[{ title, subtitle, items: [{ name, icon }] }]`
- `icon` is a filename string (e.g. `'react.svg'`) or `null`.
- Uses `import.meta.glob` map to resolve icon URLs.

#### `CapabilitiesSection`
No props. Reads `capabilities` from `content.js`.
- `capabilities` array shape: `[{ number, titleLines: [string], description }]`
- Hover inversion uses Tailwind `group` + `group-hover:` utilities — no JS state needed.

#### `ContactSection`
No props. Reads `personal` (email, socials) from `content.js`.
- Reads `import.meta.env.VITE_WEB3FORMS_KEY` at runtime.
- If key is empty/undefined: renders inline error message, submit button is `disabled`.
- Form state managed with `useState` for field values and submit status.

#### `Footer`
No props. Reads `personal` (fullName, copyright, footerLinks) from `content.js`.

### Component File Map

```

  HeroSection.jsx

```

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Data-driven card count

*For any* array of N project objects in Content_Store, the `ProjectsPanel` component SHALL render exactly N `ProjectCard` elements — no more, no fewer.

**Validates: Requirements 5.5, 13.6**

### Property 2: Data-driven certificate count

*For any* array of M certificate objects in Content_Store, the `CertificatesPanel` component SHALL render exactly M `CertificateCard` elements — no more, no fewer.

**Validates: Requirements 5.6, 13.7**

### Property 3: Slug-based project lookup

*For any* array of project objects each with a unique `slug`, looking up a project by slug SHALL return exactly the object whose `slug` field matches, and looking up a slug not present in the array SHALL return `undefined` (triggering redirect to `/`).

**Validates: Requirements 7.11**

### Property 4: Contact form field validation

*For any* string composed entirely of whitespace characters (including the empty string), submitting the contact form with that string as the Name, Email, or Message field SHALL prevent form submission and preserve the current form state.

**Validates: Requirements 11.6**

### Property 5: PlaceholderImage dimensions preservation

*For any* image slot given explicit `width` and `height` style values, the `PlaceholderImage` component SHALL render a block with exactly those dimensions — the placeholder never collapses to zero size or overflows its container.

**Validates: Requirements 14.1, 14.2**

## Error Handling

### Image Load Failures

Every `<img>` tag that references a `public/` path uses the `onError` handler pattern:

```jsx
const [imgError, setImgError] = useState(false);
// ...
{imgError ? (
  <PlaceholderImage className="w-full h-full" />
) : (
  <img
    src={src}
    alt={alt}
    className="w-full h-full object-cover"
    onError={() => setImgError(true)}
  />
)}
```

This applies to: hero portrait, about photo, project cover images, project detail images, certificate images. The `PlaceholderImage` block is styled with `bg-image-bg` (`#eeeeed`) and occupies the exact same dimensions as the intended image.

### Missing Web3Forms API Key

`ContactSection` reads `import.meta.env.VITE_WEB3FORMS_KEY` at render time:

```jsx
const apiKey = import.meta.env.VITE_WEB3FORMS_KEY;
const keyMissing = !apiKey || apiKey.trim() === '';
```

When `keyMissing === true`:
- A visible inline error message is rendered below the form heading: *"Contact form is not configured. Please set the VITE_WEB3FORMS_KEY environment variable."*
- The submit button is rendered with `disabled` attribute and reduced opacity.
- No POST request is ever attempted.

### Web3Forms API Errors

On a non-2xx HTTP response or network failure, `submitStatus` is set to `'error'` and an error message is rendered below the submit button. The form fields remain populated so the user can retry.

### Invalid Project Slug

In `ProjectDetailPage`:

```jsx
const { slug } = useParams();
const project = projects.find(p => p.slug === slug);
if (!project) return <Navigate to="/" replace />;
```

This is evaluated synchronously at render time — no loading state is needed because all data is bundled at build time.

### 404 Routes

`App.jsx` includes a catch-all route that redirects all unmatched paths to `/`:

```jsx
<Route path="*" element={<Navigate to="/" replace />} />
```

### Mobile Menu Accessibility

When the mobile hamburger menu is open, focus is trapped within the dropdown. The hamburger button toggles `aria-expanded`. Nav links close the menu on click.

### Certificate Modal Body Scroll Lock

When `CertificateModal` mounts:
```js
document.body.classList.add('overflow-hidden');
return () => document.body.classList.remove('overflow-hidden');
```
This prevents background scroll while the modal is open and restores it on unmount.

## Testing Strategy

### PBT Applicability Assessment

This project is primarily a UI rendering application with data-driven components, a contact form, and routing logic. The majority of features involve:
- UI rendering from static data (not suitable for PBT)
- Image fallback rendering (visual output, not computable properties)
- External API side effects — Web3Forms POST (not suitable for PBT)
- CSS-driven hover states (not computable)

However, three areas contain logic with universal properties suitable for property-based testing:
1. **Data-driven rendering** — card count must equal array length for any N
2. **Slug lookup** — find-by-slug must be correct for any array of projects
3. **Form validation** — whitespace rejection must hold for any whitespace string

### Unit Tests (Vitest + React Testing Library)

Unit tests focus on specific scenarios, edge cases, and component integration points.

**PlaceholderImage**
- Renders without an `<img>` tag
- Applies the passed `className` and `style` props

**Navbar**
- Renders all nav links from `navLinks`
- Hamburger button toggles menu visibility on mobile viewports
- Active link receives the active style class

**WorkSection / TabSwitcher**
- Renders "Projects" tab as active on initial load
- Switching to "Certificates" tab hides the projects panel
- Switching back to "Projects" tab hides the certificates panel

**ProjectCard**
- Renders title, description, year, and category from the project object
- "View details" link points to `/projects/<slug>`
- Renders `PlaceholderImage` when `onError` fires on the cover image

**CertificateCard + CertificateModal**
- Clicking a `CertificateCard` opens the modal
- Clicking the backdrop closes the modal
- Clicking the close button closes the modal
- Grade pill only renders when `grade` is non-null
- PDF button only renders when `pdfUrl` is non-null

**ContactSection**
- Renders inline error when `VITE_WEB3FORMS_KEY` is not set
- Submit button is disabled when API key is missing
- Renders success message after a mocked successful POST
- Renders error message after a mocked failed POST
- Does not submit when required fields are empty

**ProjectDetailPage**
- Renders project details when a matching slug is found
- Redirects to `/` when slug is not found
- GitHub button only renders when `githubUrl` is non-null
- Live Demo button only renders when `liveUrl` is non-null

### Property-Based Tests (Vitest + fast-check)

Each property test runs a minimum of 100 iterations. Tests are tagged with a comment referencing the design property they validate.

**Property 1 — Data-driven card count**
```js
// Feature: malvin-portfolio, Property 1: data-driven card count
// For any array of N project objects, ProjectsPanel renders exactly N ProjectCards
fc.assert(fc.property(
  fc.array(projectArbitrary(), { minLength: 0, maxLength: 20 }),
  (projects) => {
    render(<ProjectsPanel projects={projects} />);
    const cards = screen.queryAllByTestId('project-card');
    return cards.length === projects.length;
  }
), { numRuns: 100 });
```

**Property 2 — Data-driven certificate count**
```js
// Feature: malvin-portfolio, Property 2: data-driven certificate count
// For any array of M certificate objects, CertificatesPanel renders exactly M CertificateCards
fc.assert(fc.property(
  fc.array(certificateArbitrary(), { minLength: 0, maxLength: 20 }),
  (certificates) => {
    render(<CertificatesPanel certificates={certificates} />);
    const cards = screen.queryAllByTestId('certificate-card');
    return cards.length === certificates.length;
  }
), { numRuns: 100 });
```

**Property 3 — Slug-based project lookup**
```js
// Feature: malvin-portfolio, Property 3: slug-based project lookup
// For any array of projects with unique slugs, findBySlug returns the correct object or undefined
fc.assert(fc.property(
  fc.array(projectArbitrary(), { minLength: 1, maxLength: 20 }),
  (projects) => {
    // Positive case: existing slug always finds the correct project
    const target = projects[0];
    const found = projects.find(p => p.slug === target.slug);
    if (found?.title !== target.title) return false;
    // Negative case: absent slug returns undefined
    const notFound = projects.find(p => p.slug === '__not_a_real_slug__');
    return notFound === undefined;
  }
), { numRuns: 100 });
```

**Property 4 — Contact form rejects whitespace-only input**
```js
// Feature: malvin-portfolio, Property 4: contact form whitespace validation
// For any string composed entirely of whitespace, form submission is prevented
fc.assert(fc.property(
  fc.stringOf(fc.constantFrom(' ', '\t', '\n', '\r')),
  (whitespace) => {
    const { getByLabelText, getByRole, queryByText } = render(<ContactSection />);
    fireEvent.change(getByLabelText(/name/i), { target: { value: whitespace } });
    fireEvent.click(getByRole('button', { name: /send/i }));
    // The success message should NOT appear
    return queryByText(/message sent/i) === null;
  }
), { numRuns: 100 });
```

**Property 5 — PlaceholderImage preserves dimensions**
```js
// Feature: malvin-portfolio, Property 5: PlaceholderImage dimensions
// For any explicit width/height, PlaceholderImage renders a block with those dimensions
fc.assert(fc.property(
  fc.integer({ min: 10, max: 2000 }),
  fc.integer({ min: 10, max: 2000 }),
  (width, height) => {
    const { container } = render(
      <PlaceholderImage style={{ width: `${width}px`, height: `${height}px` }} />
    );
    const el = container.firstChild;
    return el.style.width === `${width}px` && el.style.height === `${height}px`;
  }
), { numRuns: 100 });
```
